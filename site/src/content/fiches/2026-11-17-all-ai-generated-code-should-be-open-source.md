## Résumé
L'auteur, Jakub Jankiewicz, défend la thèse selon laquelle tout code généré par l'IA devrait être publié en Open Source. Son argumentation repose sur deux piliers : un argument éthique (les modèles d'IA ont été entraînés sur du code libre et du contenu Stack Overflow sous licence Creative Commons, sans attribution ni permission) et un argument juridique (le code purement généré par IA, sans auteur humain, ne devrait pas être protégeable par le droit d'auteur, par analogie avec le précédent du « Monkey Selfie »). Il reconnaît que les lois varient selon les pays et propose que développeurs et entreprises publient explicitement ce code sous licence libre ou CC0 pour une approche équitable à l'échelle mondiale.

## Points clés
- Les modèles d'IA ont été entraînés sur un corpus massif de code Open Source et de contenus Stack Overflow/Stack Exchange (sous licence Creative Commons exigeant une attribution), scrapés sans permission ni attribution.
- Transformer ce savoir collectif en code propriétaire fermé est qualifié de « blanchiment de licence » (license laundering).
- Argument juridique central : le code purement généré par IA n'ayant pas d'auteur humain, il ne devrait pas être copyrightable — par analogie avec le précédent américain du « Monkey Selfie ».
- Le U.S. Copyright Office a repris ce précédent pour l'IA, et Wikimedia Commons exige que les images purement générées par IA soient taguées domaine public.
- Le droit d'auteur diffère selon les juridictions (ex. le Royaume-Uni accorde une protection limitée aux œuvres générées par ordinateur), d'où la proposition de publier ce code sous licence Open Source ou CC0.
- Distinction entre code modifié/relu par un humain et code quasi entièrement automatisé (où l'humain ne fait qu'écrire des prompts), ce dernier devant selon l'auteur obligatoirement être Open Source.

## Analyse approfondie
C'est peut-être une opinion tranchée, mais je crois fermement que tout code généré par l'IA devrait être Open Source. Voici pourquoi.

Tout d'abord, les modèles d'IA ont été entraînés sur un corpus massif de code Open Source écrit depuis que RMS a annoncé le projet GNU et le mouvement du logiciel libre (Free Software Movement). Ce code a simplement été récupéré (scrapé) sur Internet et utilisé sans permission ni attribution appropriée. Les modèles ont également été entraînés sur Stack Overflow et les projets associés de Stack Exchange, qui sont publiés sous des licences Creative Commons exigeant légalement une attribution. Transformer ce savoir collectif en code propriétaire et fermé ressemble à du blanchiment de licence (license laundering).

La deuxième raison est juridique : le code purement généré par l'IA n'est pas écrit par un humain, ce qui signifie qu'il ne devrait pas être protégeable par le droit d'auteur (copyright). Aux États-Unis, le fondement de ce principe remonte au célèbre litige du « Monkey Selfie », qui a établi que des non-humains ne peuvent détenir de droits d'auteur — un précédent repris plus tard par le U.S. Copyright Office à propos de l'IA. Suivant la même logique, Wikimedia Commons exige que toutes les images purement générées par IA soient étiquetées comme relevant du domaine public.

Cependant, les lois sur le droit d'auteur diffèrent à travers le monde. Par exemple, des pays comme le Royaume-Uni accordent une protection limitée du droit d'auteur aux œuvres générées par ordinateur. Pour rendre les choses équitables dans toutes les juridictions, et pour honorer l'écosystème ouvert qui a rendu l'IA possible, les développeurs et les entreprises devraient explicitement publier le code généré par IA sous des licences Open Source, ou le verser dans le domaine public via la licence Creative Commons Zero (CC0).

Bien sûr, le code n'est jamais 100 % manuel ni 100 % automatisé. Cependant, les développeurs s'appuient de plus en plus sur l'IA sans même relire le résultat généré, et encore moins le modifier pour l'adapter à leurs besoins spécifiques. Ce type de code, pour lequel les humains ne fournissent que peu d'effort — à part écrire des prompts —, devrait assurément être Open Source.

## Pourquoi ça compte
Ce billet pose une question juridique et éthique encore mal tranchée — qui détient les droits sur le code généré par IA — à un moment où l'adoption des assistants de code explose ; les entreprises qui s'appuient massivement sur le code généré par IA sans révision humaine devraient suivre l'évolution de cette jurisprudence et de ces normes de licence.
