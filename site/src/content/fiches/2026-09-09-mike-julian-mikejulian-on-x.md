## Résumé
Mike Julian, dans un post sur X, explique que son équipe chez DuckbillHQ a quasiment abandonné la revue de code après s'être retrouvée avec 60 pull requests ouvertes pour une équipe de seulement cinq personnes. Les PR s'étaient accumulées sur plusieurs semaines, et l'équipe a réalisé qu'il faudrait l'équivalent de deux jours de travail rien que pour les traiter. Ce constat a été le déclencheur d'un changement de pratique.

## Points clés
- L'équipe de DuckbillHQ (5 personnes) a accumulé 60 PR ouvertes en quelques semaines.
- Le traitement de ce backlog aurait nécessité environ deux journées entières consacrées uniquement à la revue de code.
- Face à ce constat, l'équipe a décidé d'abandonner (en grande partie) la revue de code systématique.
- L'anecdote illustre une tension courante entre rigueur de process et vélocité pour les petites équipes.

## Pourquoi ça compte
Ce témoignage illustre un débat récurrent en ingénierie logicielle sur le coût réel de la revue de code systématique face à la vélocité des petites équipes, une réflexion pertinente pour toute veille sur les pratiques de développement.
