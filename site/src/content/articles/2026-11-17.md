# 104 titres de métier dans l'arbre généalogique tech. Une seule vraie question : qui est responsable ?

Combien de métiers l'informatique a-t-elle inventés depuis les années 1940 ? Un ingénieur vient d'en recenser 104, de « Computer » — un humain, pas une machine — jusqu'à « AI Agent / Context Engineer » aujourd'hui [[1](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fzwischenzugs.com%2F2026%2F11%2F03%2Fa-family-tree-of-software-job-titles%2F%3Futm_source=tldrdev/1/010001a1e44bb3de-bee98666-dd84-4f36-a215-d481a974c08b-000000/Whmu01KNdIzdTlLb5a9IqZQNGe1hOC7KviVyXxdYhM8=452)]. Sur le papier, les intitulés n'ont jamais été aussi nombreux. Sur le terrain, c'est l'inverse qui se joue : les rôles se resserrent vers un seul profil, capable de tout faire avec un assistant IA ouvert à côté du clavier.

### Un arbre qui n'arrête jamais de pousser

Cet arbre généalogique classe les 104 titres en sept familles : développement, analyse-architecture-leadership, opérations-infrastructure, réseaux-sécurité, données et IA, qualité-test, support client [[1](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fzwischenzugs.com%2F2026%2F11%2F03%2Fa-family-tree-of-software-job-titles%2F%3Futm_source=tldrdev/1/010001a1e44bb3de-bee98666-dd84-4f36-a215-d481a974c08b-000000/Whmu01KNdIzdTlLb5a9IqZQNGe1hOC7KviVyXxdYhM8=452)]. Chaque flèche raconte une filiation : le « webmaster » des années 90 qui éclate en dev front, ops et support, le « DevOps » qui glisse vers SRE puis platform engineering sans que le travail change vraiment de nature.

Le détail le plus troublant, c'est l'origine du mot « coder ». En 1947, Goldstine et von Neumann séparaient déjà la réflexion — réservée aux mathématiciens — de la traduction en instructions machine, jugée tâche subalterne. Puis coder est devenu la partie noble du métier. Aujourd'hui, avec l'IA qui produit du code à la chaîne, on dirait que l'histoire repart dans l'autre sens.

### Les étiquettes se multiplient, le travail converge

C'est exactement ce que décrit Joe Reis, coauteur de *Fundamentals of Data Engineering* [[2](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fjoereis.substack.com%2Fp%2Fdo-data-roles-have-a-future%3Futm_source=tldrdata/1/010001a1e4102a7f-1707763f-bcae-44fd-9622-7435fac8cdc6-000000/_qzxbEgzVb5KMA6N7Kix-cwssFaek9s8zUc3hoTgz10=452)]. Sa dernière enquête communautaire montre que 80 % des répondants utilisent l'IA chaque jour, mais que seuls 10 % l'ont vraiment intégrée dans leurs flux de travail — et que 89 % butent encore sur des problèmes basiques de modélisation de données.

Son explication : l'IA rend la *production* — écrire le code, le pipeline, le dashboard — quasiment gratuite. Ce qui reste cher, ce sont l'*interprétation* (que signifie vraiment ce chiffre ?) et l'*accountability* (qui assume si ça casse ?). Pour lui, data engineers, analytics engineers, analystes, data scientists et architectes convergent vers un même profil : le « data practitioner », jugé sur ce qu'il sait exécuter plutôt que sur son titre.

### Tout le monde fait de l'analyse, personne ne sait d'où vient le chiffre

Cette convergence a un symptôme très concret : le self-service analytics est passé du programme piloté par la DSI à la fenêtre de chat ouverte sur le bureau de n'importe qui [[3](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fwww.timextender.com%2Feveryone-is-an-analyst-now%3Futm_campaign=58826149-FY26-CA-DG-Analyst-WP-TLDRDATA-Global%26utm_source=tldrdata%26utm_medium=newsletter%26utm_content=analysts-wp/1/010001a1e4102a7f-1707763f-bcae-44fd-9622-7435fac8cdc6-000000/GUDXpo336jWzzw7P8fEycYt9KOs2GEe6p-FAU4flD9Q=452)]. Un manager commercial exporte un rapport, le colle dans un assistant, récupère un graphique propre en une minute.

Le problème, c'est que personne ne sait ce qu'il y a derrière ce graphique.

> « What nobody can say is which definition of revenue it used, which date it counted, or whether it saw the whole customer list. »

Quand ce chiffre ne colle pas avec le dashboard officiel, c'est l'équipe data qui récupère la question — sans avoir jamais vu la requête.

### Produire plus vite ne veut pas dire livrer plus sûr

Le même déséquilibre se retrouve côté ingénierie logicielle. L'étude annuelle de New Relic, menée auprès de 2 575 responsables IT et ingénierie, pointe que 78 % des équipes constatent plus d'incidents malgré une vitesse de livraison de code en hausse — ce qu'ils appellent la « phantom velocity » [[4](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fnewrelic.com%2Fresources%2Freport%2Fobservability-forecast%2F2026%3Futm_campaign=FY27-Q2--GLOBAL--observability-forecast-2026-launch%26utm_source=tldr%26utm_medium=email%26utm_content=tldr_newsletter/1/010001a1e424ca05-1ae21283-8647-4180-9e21-bb31cf8392ed-000000/NyM2d8SmhmslGYtYJDGNW7yIM_XZNKQhwkjuGSiYGu8=452)]. Un quart des équipes font tourner des agents IA en production sans supervision réelle, et le nombre moyen d'outils de monitoring est remonté de 4,4 à 5,0 par équipe.

Côté CI, le COO de GitHub annonçait en avril 2026 que la plateforme traitait 275 millions de commits par semaine — un rythme annuel de 14 milliards, contre environ 1 milliard en 2025 — et 2,1 milliards de minutes GitHub Actions consommées la même semaine, contre 500 millions par semaine en 2023 [[5](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fwww.freecodecamp.org%2Fnews%2Fspeed-up-ci-in-the-age-of-ai-written-code%2F%3Futm_source=tldrdev/1/010001a1e44bb3de-bee98666-dd84-4f36-a215-d481a974c08b-000000/ALh3RjF9BIJ9AuJmZA1W1VAns6WN6c-z5qSS9_TiJIo=452)]. Un pipeline de 15 minutes se tolère quand un humain pousse deux fois par jour. Quand un agent ouvre dix pull requests dans l'après-midi, ce même pipeline devient une file d'attente.

> « You wait for results, agents wait to retry, and the time saved writing code is lost checking it. »

### Et quand plus personne n'a vraiment écrit le code, qui est responsable ?

Cette question d'accountability se pose aussi version juridique. Un développeur argumente que tout code généré par IA devrait être placé en open source ou dans le domaine public, puisque les modèles ont appris sur du code libre scrapé sans permission, et que les décisions de justice sur le « monkey selfie » excluent déjà les non-humains du droit d'auteur [[6](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fjakub.jankiewicz.org%2Fblog%2Fai-code-open-source%2F%3Futm_source=tldrdev/1/010001a1e44bb3de-bee98666-dd84-4f36-a215-d481a974c08b-000000/A0SWeMd2XZu5tup6_XLsv5Ok8mvqs0hclVylMJCJbzA=452)]. Le raisonnement est discutable, mais la question qu'il pose ne l'est pas : si une IA a écrit le code sans qu'un humain le relise vraiment, qui en porte la responsabilité le jour où ça casse ?

C'est la même question que pose Joe Reis sur les données, que pose New Relic sur la prod, que pose Timextender sur le chiffre qui ne colle pas. Les titres se sont multipliés pendant quatre-vingts ans pour découper le travail en tâches de plus en plus fines. L'IA recolle tout ça en un geste. Reste à savoir qui, dans l'organigramme, a encore le dernier mot.
